## 修复 Tailwind v4 + SCSS 配置（E:\blog）

## 二、BlogCard `group-hover:text-shadow-*` 排查（当日更晚）
- 现象：`<h2 class="group-hover:text-shadow-light-button-hover">` hover 无反应，怀疑 group 失效。
- 结论：**group 没坏**。构建产物里已生成
  `.group-hover\:text-shadow-light-button-hover:is(:where(.group):hover *){--tw-text-shadow-color:#969780}`。
  真正原因：`text-shadow-<color>` **只设置阴影颜色**，元素本身没有任何阴影（缺 `text-shadow-<尺寸>`），所以看不见。
- 修法：再配一个尺寸 → `text-shadow-light-button-hover group-hover:text-shadow-lg`。
- 现状更正：用户后来把 `main.scss` 改回自带 `$color-*`，与 `main.css` 的 `@theme` 重复，建议去重。
- 环境坑：本机跑 `nuxt build` 会被 WorkBuddy 的 safe-delete 守卫拦住（清 `.nuxt/dist`、`.output` 时文件数 > 50 → SAFE_DELETE_BULK_CONFIRM_REQUIRED），与项目代码无关。
- 用 `@tailwindcss/node` 的 `compile()` 直接编译验证（免跑 nuxt build）：`compile(css,{base})` → `compiler.build([候选类])`。
  - 结论：`text-shadow-lg` 生成 `text-shadow: … var(--tw-text-shadow-color, rgb(0 0 0/0.1)) …`；`text-shadow-light-button-hover` 生成 `--tw-text-shadow-color:#969780`（@supports 内为 `color-mix(in oklab, var(--color-light-button-hover) var(--tw-text-shadow-alpha), transparent)`）。
  - 层顺序实测为 `properties, theme, base, components, utilities`，所以 utilities 里的颜色变量不会被 properties 层的 `initial` 盖掉 → 机制本身没问题。
  - 因此"看不到颜色"多半是：配色太暗（#969780 偏橄榄灰）+ 把 shadow 色误当文字色 + dev 缓存未刷新。

## 三、右侧导航改造成"弧形（扇形）虚拟列表"
- 起因：`RightTabWithNav.vue` 里定义了 `@mixin radial($radius:80px)`（`translate(-50%,-50%) rotate(θ) translateY(-r) rotate(-θ)`）+ `link-angle(i)=i*30deg`，但 **`.doc-link{}` 是空的，`@include` 从没被调用** → 公式根本没参与编译，所以"失效"。
- 认知纠正：`useVirtualList` 与"绕心旋转"是**正交**的两件事。虚拟化只减少 DOM 数量；旋转是几何。二者结合的正当理由只有一个——**轨道是弧形的虚拟列表**：轨道仍然是直线的（`useVirtualList` 提供 scrollTop 与窗口），把"轨道距离"换算成圆心角即可。
- 新增 `app/components/FanVirtualList.vue`（可复用容器）：
  - `stepRad = itemHeight / radius`（每条跨越的固定圆心角），`theta = (progress - index) * stepRad`，`progress = scrollTop / itemHeight`。
  - 位置：`x = anchorX + r*(1-cosθ)`、`y = anchorY - r*sinθ`（圆心在"锚点向右 r"处，θ=0 落在锚点，两端向右微凸）。
  - 朝向：`orientation` = `tangent`(θ，扇骨沿弧切线) / `radial`(θ-90°，指向圆心) / `upright`(0)。
  - **关键结构**：视觉层 `.fan-list__stage` 用 `position: sticky; top: 0; overflow: hidden` 钉在滚动视口上，条目在里面 `absolute + translate3d`。sticky 让条目**留在 scroller 内部**（滚轮/触摸/键盘原生滚动全都能用，不用手写 wheel 转发），`overflow:hidden` 又阻止条目扩大 scrollable overflow（否则会"滚不到头"）。
  - `wrapperProps` 的 `marginTop + height` 恒等于 totalHeight，所以内容总高恒定、不会抖动；`overscan = ceil(maxAngle/stepDeg)+3` 保证窗口比可见角度范围宽，否则弧上的条目会被提前卸载。
  - 暴露 `scrollToIndex`。
- 实测几何（itemHeight=56, radius=520, 容器 220×520）：步进 6.17°，可见半角 ±30°，横向外凸 69.7px。卡片宽 10rem + `anchorX=0.32` 时基本不裁切。
- 新增 `demo/fan-list-lab.html`：纯前端调参台（滑杆调 itemHeight/radius/maxAngle/anchorX/anchorY/fade + orientation 分段器），画出圆心/半径虚线、显示渲染条数与窗口区间，一键复制 Vue 参数。改参数在这里调好再抄回组件。
- 环境注意：`@vue/compiler-sfc` 在 pnpm 下不在根 node_modules，要用绝对路径 `node_modules/.pnpm/@vue+compiler-sfc@3.5.43/node_modules/@vue/compiler-sfc/dist/compiler-sfc.cjs.js` 引入做语法自检。
- 遗留：`main.scss` 里仍有一份重复的 `$color-light-*`，与 `main.css` 的 `@theme` 重复定义，建议去重。

## 四、扇形列表接入 `useWindowScroll`（当日更晚）
- 需求：让扇形跟随**页面滚动**旋转。
- 关键决策：**不能各驱动各的**。若窗口滚动只影响 `progress`，`useVirtualList` 的取窗口仍按内部 `scrollTop` 算 → 扇形会大片空白。所以做法是把**窗口滚动的增量转发进内部轨道**（`el.scrollTop += (y - prev) * windowFactor`），`scrollTop` 始终是唯一真相，取窗口逻辑零改动，两种输入还能自然叠加。
- 新增 props：`driver: 'self' | 'window' | 'both'`（默认 `self`）、`windowFactor`（默认 0.5，即页面滚 1px → 轨道前进 0.5px）。
  - `self`：只靠内部滚动条（原行为）。
  - `window`：内部滚动条换成 `overflow: hidden`（**用户不可滚、脚本可滚**），滚轮穿透给页面。
  - `both`：叠加。`self/both` 保留 `overflow:auto` + `overscroll-behavior: contain`，所以悬停在扇形上滚轮只动扇形、不会链到页面造成双重推进。
- 坑：`containerProps.style` 是内联样式，会压过 class，所以要用 computed 把 `overflowY` 换掉再 `v-bind`（`const { style, ...rest } = containerProps`）。
- 坑：锚点跳转/滚动恢复会产生巨大 delta，必须过滤（`Math.abs(delta) > 2000` 直接丢）。
- 手感：`windowFactor` 取 `轨道总高 / 页面可滚高度`（= `count*itemHeight / (scrollHeight - innerHeight)`）时，"页面滚到底"刚好等于"扇形走完全程"，侧栏导航通常要这个。
- 顺带：`RightTabWithNav` 用户自己调了 `.fan{height:min(100vh,34rem)}`、`.doc-link{width:8rem}`，并删掉了我写的模板注释 —— 8rem + anchorX 0.32 刚好不裁切。
- 实验台 `demo/fan-list-lab.html` 改成**真正的长页面**：左侧 fixed 控制面板 + 右侧 fixed 扇形视口 + 中间长文提供窗口滚动；新增 driver 分段器、windowFactor 滑杆、"按页高自动匹配"按钮，读数区同时显示 `window.scrollY` / `轨道 scrollTop` / `progress`。

## 五、推翻「增量转发」，改为直接追踪页面进度（当晚）
- 用户反馈：参照 `RightTab` 的设计**直接追踪滚动进度**即可，不需要增量实现。
- 重构 `FanVirtualList.vue`：
  - `driver` 简化为 `'self' | 'window'`，删除 `'both'` —— window 模式下滚轮本来就穿透给页面，"叠加"没有意义。
  - 删除 `windowFactor` 和增量 watch。改为：`pageProgress = scrollY / (scrollHeight - innerHeight)`（0~1，与 RightTab 同款；scrollHeight 每次现读，内容变高后下次滚动自动修正），`windowIndex = pageProgress * windowSpan`。新增 prop `windowSpan`（页面整程映射多少个条目，0 = 整份列表）。
  - `progress` 在 window 模式**直接取 windowIndex**（视觉零延迟）；内部轨道 scrollTop 只是被 `watchEffect` 以**绝对值**同步过去，让 `useVirtualList` 取到正确的窗口——它不再是真相源。
- **坑 1（实测发现，重要）**：`overflow:hidden` + `overscroll-behavior:contain` 会把滚轮**整块吞掉**——轨道不滚、页面也不滚，光标停在扇形上就彻底卡住。window 模式必须把 `overscroll-behavior` 放开为 `auto`（self 模式才用 `contain`）。CSSWG 表里的 ❌ 只表示"滚轮不会滚这个容器"，**不代表事件会链给父级**，别按表格想当然。
- **坑 2**：轨道 scrollTop 上限 = `总高 - 容器高`，不补尾巴的话末尾 `容器高/itemHeight` 条**永远到不了前位**。修法：window 模式在 wrapper 后面加 `.fan-list__tail`（高度 = boxH），上限正好变成 `items.length * itemHeight`。
- 验证手段（零依赖）：Node 22 自带 `fetch` + 全局 `WebSocket`，直接 CDP 驱动本机 Chrome（`chrome.exe --headless=new --remote-debugging-port=9222 --user-data-dir=…`），`Input.dispatchMouseEvent {type:'mouseWheel'}` 能产生**真实滚动**。实测：滚轮打在扇形上 y 900→1500、前位 6.22→10.37；滚到页底最后一条距前位 -1px；self 模式滚轮只动轨道（300→700）、页面不动。
- 环境注意：本会话里 PowerShell 读不到 stdout、bash 的 coreutils（ls/head/dirname）缺失，一律改用 `node -e` / node 脚本做文件与探测操作。

## 十、查询优化（select 元数据）+ 无限滚动（10-03 凌晨）
- **关键事实**：`@nuxt/content` 的 SQLite 表列只有 `id, title, body, description, extension, meta, navigation, path, seo, stem, __hash__`
  —— **没有 `type`，也没有 `date`**！所以 `.select(...,'type')` / `.order('date',...)` 会直接报错。
  - `type` 一直是由 path 推导的（`getTypeFromPath`）；要按日期排序必须先给 collection 加 schema + 在 front-matter 写 date。
  - 表结构可直接读 `.nuxt/content/sql_dump.txt`（或 `.data/content/contents.sqlite`）确认，别猜字段。
- 优化：`queryCollection('content').select('path','title','description').order('path','ASC').all()` —— 不拉 body（minimark AST）。
  - 验证：抓 SSR HTML，`'minimark'` 与 `"body":` 键**都消失**了 → 确实没再取正文。
- **副作用（要记住）**：不取 body 后，搜索只能覆盖 title/description/path/type，**正文不再参与匹配**（`documentText` 里的 flattenNode 已删）。要全文搜索得单独做索引或保留 body。
- 类型调整：`ContentDocument` 改成极简（path/title/description/type）；新增 `ContentMeta`（select 出来的形状）；`useContentSummary` 的参数类型改成 `ContentCollectionItem`（它处理的是含 body 的完整页面，跟列表页不是一回事）。
- **分页策略（重要决策）**：列表做**客户端增量展示**，不用服务端 `.skip()/.limit()`。
  - 理由：搜索/筛选本来就需要全量元数据（否则搜不到未加载的文档），元数据一定已在 store 里，再按页去服务端取 = 把同样的行重复取一遍，反而更慢。
  - 新增 `app/composables/useInfiniteList.ts`：`visibleCount` 起点 pageSize，`useIntersectionObserver` 监听底部哨兵，滚到附近 `visibleCount += pageSize`；筛选数组换新引用时自动回到第一页。
  - **坑**：IntersectionObserver 只在「进入/离开」触发 —— 新增内容仍填不满视口时哨兵一直可见，不会再触发 → 加载完必须 `nextTick` 后自查 `getBoundingClientRect` 若仍在视口就继续递归加载。
  - `minSpin`（默认 320ms）是最短展示时长，避免 spinner 闪一下看不见（不是假延迟）。
- 新增 `app/components/SpinCircle.vue`：最简单的转圈（border + border-top-color + rotate），颜色写死调色板值（SFC scoped 读不到 main.scss 的 `$color-*`）：轨道 #E0E0F0、旋转头 #969780。
- 验证（CDP + 临时造文档）：临时建 12 篇 md（共 16 篇）→ 初始渲染 **10 条**、滚动过程**捕获到 spinner**、加载完 **16 条**且出现「没有更多了」；删掉临时文档后恢复 4 条。
