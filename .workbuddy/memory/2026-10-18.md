  那个 header 是 `position: fixed`，紧跟其后的兄弟会被它压住，必须落在 `.index-body` 的
  `padding-block` 让位区里（`.index-body` 已有 `padding-block: calc(4rem + 1.25rem) 3rem`）。
- 主题适配（外部组件常有的三处硬伤，改一处不够）：
  1. `background: #0e100f` → `var(--ui-canvas)`；
  2. **两侧渐隐遮罩的渐变起点也是 `#0e100f`** —— 只改底色不改这里，会在浅色页面上留下两条深色竖带；
  3. `border-top/bottom: #2a2c30` → `var(--ui-line)`；文字 `#7c7c6f` → `var(--ui-text-muted)`，

  另外去掉了 `.dot` 的 `box-shadow: 0 0 10px currentColor` —— 霓虹光晕是深底专属，浅底上像脏污；
  小圆点保留各家品牌色（那是这条带子唯一的彩色）。
- **`gsap` 必须提成直接依赖**：原来只有 `gsap-nuxt-module`（且未注册进 `nuxt.config` modules），
  pnpm 隔离模式下 `node_modules/gsap` 不存在，`import { gsap } from 'gsap'` 解析不了
  （`require.resolve('gsap')` → MODULE_NOT_FOUND）。已 `pnpm add gsap@^3.15.0`。
  `app/components/gsap/` 下 11 个 GSAP 组件都是素材，只有 GsapMarquee 被真正引用。
- 技术栈条目：补了 Three.js / React / .NET / ASP.NET / PostgreSQL / MongoDB / RabbitMQ，
  共 16 条。Three.js 官方是黑标，暗底不可见，取官网链接色 `#049EF4`。
- 无障碍：第二组 `aria-hidden`（否则读屏念两遍）；`prefers-reduced-motion` 时不起 tween，静态排一行。

## 筛选条 tag 选项的 stagger 动画

- **最终落在 `app/components/TypeDropdown.vue` 内部**，不是 index.vue。作用对象是展开后的 tag 选项
  （`.item`：全部类型 + 每个 type）。`toggle()` → `await nextTick()` → `gsap.from(tags, {...})`。
  参数：`opacity: 0, x: -12, duration: 0.4, ease: 'back.out(2)', stagger: 0.01`，收尾 `clearProps`。
- 一开始把动画做在 index.vue 的 `.filter-bar__inner > *` 上，用户要求改到组件里，那份已全部撤回
  （`git diff` 已确认 index.vue 只剩跑马灯相关改动）。
- ⚠️ **踩到的坑：CSS 动画的 `forwards` 填充优先级高于内联样式**。当时给等待态挂了
  `animation: xxx 0s 1.5s forwards` 做「JS 失效兜底」，结果填充值一直把 opacity 压成 1，
  GSAP 写的 opacity 完全失效（采样里 opacity 恒为 1.00，只有 transform 在动）。
  以后要让 GSAP 控制某个属性，就别让 CSS 动画对同一属性做 forwards 填充。

## 这个环境的操作备忘

- **on-save 格式化会吞注释**：改 `index.vue` 时，`.filter-bar` 里那段刻意注释掉的 `&::after`、
  以及两处行注释都被静默删掉了。已还原。**改完务必 `git diff` 复核无关改动。**
- **dev server 的进程残留**：`pnpm dev` 起来后 `taskkill /F /PID <父进程>` 杀不干净，
  nuxt 子进程会继续占着 3000（内存 2GB 那种），下次启动就会静默退到 3001。
  必须 `taskkill /F /T /PID`（带 `/T` 杀进程树），或者直接按端口找 PID。
  另外 Git Bash 里 `taskkill //F` 会报「Invalid argument」，要 `MSYS_NO_PATHCONV=1 taskkill /F`。
- **dev 启动会被 safe-delete 守卫拦**：Nitro 启动时要 `rm -rf .nuxt/dev`，
  该目录 422 个文件超过阈值 50 → `SAFE_DELETE_BULK_CONFIRM_REQUIRED` 直接崩。
  绕法：启动前 `mv .nuxt/dev .nuxt/dev-old`（目录不存在时守卫计数为 0）。
- 无头 Chrome 采样验证很费时间（dev 首屏水合要 10s+，一次采样十几秒），用户明确说别再做这种验证，
  有问题他会直接反馈。

## 笔记里内联 SVG 显示错乱（字溢出框、不居中、箭头丢失）

- 用户第一判断是「全局样式影响了 svg」，实际与 CSS 无关。抓页面 HTML 就看到：
  `<text x="340" y="60" textAnchor="middle" dominantBaseline="central" fontSize="14">` —— **属性名是驼峰**。
- 根因链路：md 里手写的 `<svg text-anchor="middle">` → remark/rehype 转 hast（hast 规定 props 用驼峰
  `textAnchor`）→ 存进 minimark（`["text",{...}, 文本]`，props 原样）→ `MDCRenderer` 直接把 props 当
  Vue 属性写出去。Vue 不会把驼峰转成连字符名，SVG 也不认 `textAnchor` → 整条属性被浏览器丢弃。
  症状一一对应：`font-size` 丢 → 回退继承的 16px（字撑破框）；`text-anchor` 丢 → 文字从锚点往右排；
  `stroke-width`/`marker-end` 丢 → 描边变粗、箭头消失。`fill`/`stroke` 是单词所以没受影响，看着像「只有字号和居中坏了」。
- CSS 修不了：没法按元素把 12/13/14 再赋回去。**修在内容管线**：
  新文件 `modules/svg-attributes.ts`，`nuxt.hook('content:file:afterParse')` 遍历 minimark 节点，
  仅对 `<svg>` 子树把驼峰键还原成 `text-anchor`/`dominant-baseline`/`font-size`/`class` 等。
  - **只处理 svg 子树**：代码块的 `className: ['language-x']` 由 ProsePre/MDCRenderer 在用，动它会坏高亮。
  - `viewBox`/`refX`/`refY`/`markerWidth`/`markerHeight` 本来就是驼峰，**不要**放进映射表。
  - 顺带修好了笔记里「用 `<style>` + class 画图」的那几篇（`.bx`/`.tt` 之前因为 `className` 从来没生效）。
- ⚠️ **两个连环坑**（各浪费一轮 90s 的重解析）：
  1. 改 `props` 只能**就地增删键**。`node[1] = fixProps(props)` 这种整体替换在冻结数组上**静默失败**
     （jiti 输出的 CJS 非严格模式），表现为「代码看着对、输出没变化」。
  2. 中间状态曾同时存在「`fixProps` 返回 void」+「`node[1] = fixProps(props)`」，于是把所有 props 写成了
     `undefined`（JSON 里变 `null`）→ 整站 SVG 页面 500：`propsToData ... Cannot convert undefined or null to object`。
     修好后必须 `rm -rf .data/content .nuxt/content` 强制重解析，脏库不会自己好。
- 验证姿势（快）：`node --experimental-sqlite` 直接查 `.data/content/contents.sqlite` 的 `body`，
  看 `["text",{...,"text-anchor":"middle"}]` 是否正确；再 `chrome --headless --screenshot` 一张图确认。
  内容解析要 60–90s，别在重启过程中下结论。
- 结果：SDL3 那张图现在与笔记原稿一致（字号分层 14/12/13、居中、箭头、细描边）。
  `.markdown-body svg` 的 `width:100%` 会把 680 单位的图拉到整列宽（约 900px），画面偏大但文字清晰，
  用户没提就先不动；要收紧就加 `max-width: min(<viewBox宽>px, 100%)`。
